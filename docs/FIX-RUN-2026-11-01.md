## 4. 崩溃取证：pstore 是空的

```
/sys/fs/pstore/ → total 0
```

原因不是权限：`ramoops` 模块已加载，但 DT 里 `ramoops_region` **没有 `record-size`**，只有 `size=0x200000` 与 `pmsg-size=0x200000`。ramoops 在这种情况下不注册任何 dump 记录区，所以内核崩溃从不落盘，只有 pmsg 通道（留给 bootloader 日志）。

结论：**pstore 这条路走不通**，`Save-CrashDump` 保留（无害，且若固件后续换成带 record 的 ramoops 会自动生效），但不再指望它定位崩溃。dmesg 里能拿到的线索是另一类：`init` 的 `SIGABRT`、`send_signal sig 9` 反复打到 ghostlock 线程、`slab` 占用 857MB 级、以及 vivo 自家的 `do_futex uaddr2 value wrong` 审计日志。
